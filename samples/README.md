# Sample JSON files

These files let the parsing tests run **offline**, as the brief requires, and let the notebook
fall back to saved data when there is no internet.

| File | What it is | Origin |
|---|---|---|
| `geocoding_dresden.json` | Open-Meteo Geocoding response for `name=Dresden&count=3` | Real response, captured 7 October 2026 |
| `geocoding_no_results.json` | Geocoding response when nothing matches (no `results` key) | Written by hand in the documented format |
| `forecast_dresden.json` | Open-Meteo daily forecast for Dresden, 7 days | Written by hand in the documented format; the values are **illustrative, not a real forecast** |
| `forecast_error_latitude.json` | Open-Meteo error body for an invalid latitude (HTTP 400) | Written by hand in the documented format |
| `met_no_dresden.json` | MET Norway Locationforecast 2.0 (compact) for Dresden | Generated by script in the documented format; the values are **illustrative, not a real forecast** |

The forecast endpoints could not be reached from the environment in which the project was first
built, so those samples follow the response formats in the official documentation
(<https://open-meteo.com/en/docs>, <https://api.met.no/weatherapi/locationforecast/2.0/documentation>).

**To replace them with real captured responses:** run the notebook with an internet connection and your
own email in the configuration cell. The cell "Save today's raw responses" writes
`captured_geocoding.json`, `captured_forecast.json` and `captured_met_no.json` into this folder.
The tests keep using the fixed files above, so they stay repeatable.

Data sources: Open-Meteo (CC BY 4.0, location data from GeoNames) and MET Norway (CC BY 4.0 / NLOD 2.0).
